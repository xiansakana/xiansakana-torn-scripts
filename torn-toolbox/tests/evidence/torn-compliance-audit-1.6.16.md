# Torn 工具箱 1.6.16 合规排查

核对日期：2026-10-09。对象：`Torn 工具箱-v1.6.16.user.js` 整个安装包，包括 Quick Items 和其他五个功能页。SHA256：`BAF0E396B3B944CC327C61C3987859CBC973250C1239755655FE9F3E1688C7DF`。

结论：存在必须整改的非 API 附加请求链、失焦后继续查询和无效 API Key 持续请求。明确违反仓库 AGENTS.md 的严格执行要求；对照 Torn 规则属于高风险实现，不能宣称已合规或获得官方审批。是否处罚由 Torn 工作人员裁定。此前“功能测试通过”不能证明这些行为获准。

## 规则依据及判断边界

- [Torn Rules / Scripting Abuse](https://www.torn.com/rules.php)：软件应使用官方 API，或用户手动加载且正在查看页面的数据；非 API 请求须直接、手动发起，不能抓取未查看页面或从失焦页面采集数据用于外发／提醒。
- [Velthir（Officer）2025-11-05 说明](https://www.torn.com/forums.php?a=0&b=0&f=67&p=threads&t=16514459)：一次人工输入对应一次按钮操作／动作；API 数据不受当前页面数据范围限制。
- [Torn API 文档](https://www.torn.com/api.html)：用户各 Key 合计每分钟最多 100 次请求（缓存例外以官方说明为准）；无效 Key 的重复请求可能封禁 IP，需处理失效或禁用 Key；用户应知晓 Key、数据的使用和保存方式。
- “多个请求”本身不等于多个游戏动作。本报告针对脚本自主添加的页面接口读取；不把 Torn 原生一次操作内部正常的网络行为一概判为违规。项目要求比最低可推断范围更严格，没有针对本脚本的工作人员审批。

## 1. 高风险：快捷武器及刷新串联非 API 读取

代码：安装包 2192、2470、2485、2513、2517 行；`modules/quick-items.js` 中 `loadInventory`、`useItem`、`loadEquippedMods`、`updateModAvailability`。

现存行为：
- 缓存主／副武器的装备：自动 GET 配装 → POST 装备 → 脚本调用公开入口 GET 配装 → 自动 GET Mod 可用列表。一次点击四条业务请求。
- 缓存主／副武器卸下：前置 GET 配装 → POST 卸下 → GET 配装，三条业务请求。
- 原生按钮路径仍加上前置配装读取和装备后的 Mod 列表读取。原生按钮自身请求数量不计为脚本已获额外读取许可。
- 主／副武器的 ↻ 刷新：POST 库存搜索 → GET 配装 → GET Mod 列表，三个独立读取被串联。

模拟已记录缓存卸下、装回共七条请求。设备状态只改变一次，并不能自动授权这些额外非 API 读取。

建议：自动记住配置仅复用当前页面／合规获得的响应数据；不得为自动保存先 fetch 配装。不足的数据标记未知或拆成独立手动读取。优先转发一次当前可见的原生操作，避免额外查询补全链。

## 2. 高风险：Mod 装卸后及失败时自动刷新原生配装

代码：安装包 2440、2449、2450 行；`modules/quick-items.js` 的 `toggleMod` 与 `refreshNativeLoadout`。

点击 Mod1 或 Mod2 只改变对应一项，但随后自行调用 `getEquippedItemsRequestAction()`，增加一次非 API GET；异常分支也无条件调用。模拟确认安装请求为 reattach → getEquippedItems，卸下使用 detach，遵循同一刷新路径。

建议：将真实详情更新交由单次原生操作及其既有结果，或提供独立手动核对入口。不能用“公开 API”注释混淆页面内部接口与官方 `api.torn.com`。不应在失败／超时后自动补读。

## 3. 高风险：入口有焦点检查，后续请求没有

代码：安装包 2179、2192、2384、2449—2450、2513—2517 行。

`activePage()` 只在入口或部分检查点执行；`modRequest`、`refreshNativeLoadout` 没有统一检查。若装备请求完成时用户切到其他窗口，代码仍继续读取配装和 Mod。模拟把焦点在装备响应返回时置为 false，仍记录后续两个 GET。原生主副武器分支在前置读取后有一次重新检查，这不能覆盖其余分支。

建议：每次即将新发起非 API 请求前统一检查页面可见、焦点、路径和实例；失焦时取消尚未发出的后续操作，不能自动恢复执行。已发出的请求可能已在服务器生效，不得盲目重试。

## 4. 必须修正：无效／禁用 Key 不停止监听

代码：安装包 504—516、1787—1816、1851—1900 行。

API helper 遇到非限流错误只抛异常；公司／压价监听的 catch 仅显示错误，定时器继续运行。模拟接口返回错误码 2，两个监听均在下一个 tick 再次发送同一失效 Key，监控仍显示运行。对禁用等其他错误亦缺少分类停用机制（错误码 2 已实测，其余基于代码判断）。官方 API 文档明确提醒处理无效／禁用 Key，重复无效请求可能造成 IP 临时封禁。

建议：分类处理 invalid/disabled/paused 等永久或需用户处理的错误，立即停相关任务并将 Key 标记不可用；用户换 Key 或修复权限后才允许重新启动。显示错误不等于已停止请求。

## 5. 中风险：API 限流与任务重叠缺少统一控制

代码：安装包 504、556、1409、1650、1812、1851、1896 行。

购买／出售日志、攻击分页、公司监听、压价监听各自请求，没有全局调度或共享请求预算。两个监听使用 async setInterval，缺少 in-flight 锁；模拟并发触发两次公司 tick，确认两个请求同时运行。慢请求或限流退避期间可能叠加。不同功能各自间隔一秒不能保证总量符合官方上限，也无法计算其他脚本占用的配额。

建议：使用共享节流与单任务 in-flight 锁，以完成后再安排下一次的方式调度；限流统一退避，支持取消。不把这项直接表述为“已超过 100 次／分钟”：本次确认的是缺少控制及可重叠，没有测到真实账号超限。

## 6. 需补充说明／另行确认

- API Key 通过 `GM_setValue('tornApiKey', key)` 本地保存，请求发给官方 API；Weav3r 请求只携带物品 ID，没有发现将 Key 或账号凭据发送给 Weav3r 的代码。应集中说明本地保存、各功能所需 selections、第三方公开行情来源与删除 Key 的方式，符合 API 使用告知要求。
- 收藏图标可能加载 `/images/items/.../medium.png` 静态资源。本报告业务请求统计未包含图标，不能说启动完全零网络；静态资源不等于自动获取库存，未据此独立认定违规。
- 缓存装备携带 `confirm=1`，但该参数本身不足以证明进行了两个动作或自动点击确认。若原生特定条件需要额外确认，应由用户完成，不能通过直连接口省略。本次未连接真实账号核对这类情形。
- 公司申请和部分 API／第三方字段通过拼接 `innerHTML` 渲染（1839 行等）；缺少统一转义属于潜在安全风险。是否可利用取决于上游字段过滤，本次未证明真实 API 可注入。建议使用 textContent／显式转义，保护 Key 和页面上下文。

## 未发现同类高风险行为的部分

- 购买／出售均价、攻击筛选：读取官方 API，并进行本地计算；攻击日志链接由用户点击，没有自动攻击。

- 消耗品快捷点击：一条 useItem POST，返回链接作为普通链接展示，没有自动继续点击或执行服务器脚本。本次仅确认代码路径，不作官方审批保证。
- Quick Items 启动／DOM observer 没有发现自动库存业务查询；缺实例时查询后返回，不自动接着装备；旧自动连续 Mod 恢复开关被强制关闭。
- 未发现挂机战斗、自动训练、自动买卖、验证码绕过、密码／Cookie 提取或向第三方上传配装的代码。
