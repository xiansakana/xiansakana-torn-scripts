# 1.6.17 请求链优化与本地验证

2026-10-09。仅本地模拟，没有对真实账号发起请求或动作。

## 用户操作对应行为

- 已加载装备：一次原生按钮操作；原生 Torn 自身更新不由工具箱重复触发。
- 缓存装备／卸下：一条 actionForm POST；快捷状态更新，原生详情不主动补读。
- 缺实例：一条 getSearchList POST，查询后返回；再次点击才装备。
- 库存 ↻：仅 getSearchList；不查询配装或 Mod。
- Mod1／Mod2：一条 reattach 或 detach；快捷 ✓ 即时更新；成功／失败均不补读。
- Mod资料：单独点击，一条 getUserUpgrades GET；不接着装配。
- 同步详情：单独点击，调用 Torn 公开同步入口；本地入口模拟一条 getEquippedItems GET。真实原生 UI 可能有自身关联加载，未在真实账号验证数量。

自动记住组合只使用当前可见 DOM 和已发生的同源 itemsLoadouts／itemsModsData 响应；观察 fetch 时 clone 现有响应，XHR 时观察现有 load 事件，不新增请求、不消费原始响应体。不处理失焦响应、不读取密码／Cookie、不向外部发送配装。未获取到资料时标记未知或要求单独手动读取。原生 DOM 与已有响应不足以确定实例时不猜测。

被动观察器安装前已经完成的响应无法补读；用户随后原生操作／单独同步提供数据后才能自动记住。仅恢复了部分保存 Mod 或卸下后仍保留原组合，以免 Mod2 按钮消失。

## API 与监听

共享队列的间隔为 1100ms；支持 Web Locks 时以同源锁和 GM 共享时间戳协调工具箱多标签，否则只能保证当前实例队列，并尽量参考共享时间戳。不能控制其他脚本／其他设备的 API 消耗，不能据此保证账户从不超限。

API code 1/2/10/13/18 阻止同一 Key 的自动重发；1/2/8/9/10/13/16/18 停止监听并要求用户处理。5 或 HTTP 429 统一退避。Key 被清空／更换后排队旧请求取消；已发出的请求可能仍完成，但停止后的结果不再启动监听任务。

监听使用完成后递归安排的 timeout、in-flight 锁和 runId；停止或重启后旧任务不能继续安排新一轮。公司申请和行情相关文本经过转义，Key 使用与保存范围在 UI 说明，提供删除入口。

## 验证

- compliance-audit.cjs：缓存装备两次仅两条 actionForm；Mod 安装／卸下各一条请求；独立读取不串联；入口失焦不请求，响应时失焦无后续请求。
- 相同已有 fetch／XHR 响应保存组合，没有二次抓取。
- 公司／压价错误 Key 后停止、不建立 timer；重启同一坏 Key 不再次请求。
- 两次并发模拟 tick 只一条公司请求、一次后续安排；停止后旧回调不再请求或安排任务；共享 API 间隔得到本地验证。
