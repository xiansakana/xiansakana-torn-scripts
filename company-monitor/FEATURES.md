# Company Monitor 功能说明

## 核心功能

### 1. 多 API Key 支持 ✨

**为什么需要多个 API Key？**

- **避免 API 限制**：Torn API 有请求频率限制（每分钟 100 次）
- **监控多个公司**：不同的 API Key 可以属于不同的公司成员
- **提高可靠性**：一个 Key 失效不影响其他 Key 继续工作
- **负载均衡**：分散请求到多个 Key

**配置示例：**

```env
# .env 文件
TORN_API_KEYS=key1,key2,key3,key4,key5
```

或

```json
// config.json
{
  "tornApiKeys": [
    "key1",
    "key2", 
    "key3"
  ]
}
```

**工作原理：**

每次检查时，程序会依次使用所有配置的 API Key 获取申请数据，然后合并结果并去重。

### 2. 邮件通知 📧

**支持的邮箱服务：**

- QQ 邮箱（推荐，国内最稳定）
- 163 邮箱
- Gmail
- 其他支持 SMTP 的邮箱

**通知内容：**

- 申请人姓名和 ID
- 等级
- 智力、耐力、体力劳动属性
- 申请状态
- 过期时间
- 申请消息

**邮件格式：**

HTML 表格格式，清晰易读，支持移动端查看。

### 3. Webhook 通知 🔔

支持 Discord、Slack 等 Webhook 通知。

**配置示例：**

```env
WEBHOOK_ENABLED=true
WEBHOOK_URL=https://discord.com/api/webhooks/your-webhook-url
```

### 4. 状态持久化 💾

**自动保存状态：**

- 已检查的申请 ID
- 最后更新时间
- 统计信息

**好处：**

- 重启程序不会重复通知
- 断电恢复后继续工作
- 不会遗漏任何申请

**状态文件：** `company-monitor-state.json`

### 5. 灵活配置 ⚙️

**两种配置方式：**

1. **环境变量**（推荐云端部署）
   - 适合 Fly.io、Railway 等平台
   - 安全，不会提交到 git
   
2. **配置文件**（推荐本地运行）
   - JSON 格式，易于编辑
   - 支持注释和格式化

**可配置项：**

- API Keys（支持多个）
- 检查间隔（秒）
- 邮件服务配置
- Webhook 配置

### 6. 错误处理 🛡️

**健壮的错误处理：**

- API 请求失败自动重试
- 单个 Key 失败不影响其他 Key
- 邮件发送失败不影响监控
- 详细的错误日志

**优雅退出：**

- 支持 Ctrl+C 停止
- 自动保存状态
- 清理资源

## 使用场景

### 场景 1：个人使用

**配置：**
- 1 个 API Key
- 检查间隔：60 秒
- 邮件通知

**适合：**
- 个人公司招人
- 小型公司

### 场景 2：团队使用

**配置：**
- 3-5 个 API Key（团队成员的 Key）
- 检查间隔：30 秒
- 邮件通知 + Webhook

**适合：**
- 中大型公司
- 需要快速响应申请
- 多人协作

### 场景 3：高频监控

**配置：**
- 5+ 个 API Key
- 检查间隔：10-20 秒
- 多个通知渠道

**适合：**
- 大型公司
- 竞争激烈的招聘
- 需要第一时间响应

## 性能优化

### API 请求优化

- 并发请求多个 API Key
- 智能去重，避免重复通知
- 缓存已知申请 ID

### 资源占用

- 内存占用：< 50MB
- CPU 占用：< 1%
- 网络流量：< 1MB/小时

### 可靠性

- 自动重连
- 状态持久化
- 错误恢复

## 安全性

### 敏感信息保护

- API Key 不记录到日志
- 邮箱密码加密传输
- 配置文件不提交到 git

### 最佳实践

1. 使用环境变量存储敏感信息
2. 定期更换 API Key
3. 使用邮箱授权码，不用登录密码
4. 限制 API Key 权限（只需 company 权限）

## 对比其他方案

### vs 浏览器脚本

| 特性 | 守护进程 | 浏览器脚本 |
|------|---------|-----------|
| 24/7 运行 | ✅ | ❌ 需要开浏览器 |
| 多 API Key | ✅ | ❌ |
| 邮件通知 | ✅ | ❌ |
| 配置灵活 | ✅ | ⚠️ 有限 |
| 部署难度 | ⚠️ 需要服务器 | ✅ 简单 |

### vs 手动检查

| 特性 | 守护进程 | 手动检查 |
|------|---------|---------|
| 实时性 | ✅ 秒级 | ❌ 分钟/小时级 |
| 自动化 | ✅ | ❌ |
| 不遗漏 | ✅ | ❌ 可能遗漏 |
| 工作量 | ✅ 零工作量 | ❌ 需要持续关注 |
